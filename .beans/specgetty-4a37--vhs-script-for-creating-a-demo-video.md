## OpenSpec change

`record-the-demo`, validated strict, 30 tasks. `skip_specs: true`: it is
fixtures, tapes and a make target, and no requirement of the application
changes.

Settled during exploration:

- **Fixture data**, not this repository. Three reasons, the third decisive: the
  picker publishes real project names; a recording from a working tree differs
  every week; and the difference view needs an active change, of which this
  repo has exactly one at a time and sometimes none.
- **Several tapes plus a hero.** Not about size (10 KB/s) but about what a
  change to one pane costs: a feature that moves invalidates 15 seconds.
- **`make demo` by hand for now**, the release hook deferred.
- The hero leads with the spec detail view, which has no equivalent elsewhere
  and reads as something in a still frame.
- A harbour: `harbour-app`, `tideclock`, `ferry-times`, `quay-signage`.

## Measured before writing it

- `vhs 0.11.0` and `ffmpeg` are installed. 13.1s at 1200x700 gives a 133 KB GIF.
- A trial recording drifted into the picker and showed 27 real project names,
  several of them client work. That frame is why the fixtures exist.
- Running from a non-project directory gives the `No OpenSpec project here`
  prompt, which then swallows every following key. Every tape pins its startup
  state.
- A store-backed project is fakeable, and it took four parts:
  `.openspec-store/store.yaml`, the repo's `store:` key, a registry entry whose
  `local_path` matches the store root, and `XDG_DATA_HOME`. Two of the four
  were found by recording the picker and reading `store: unresolved` off the
  row rather than from the source.
- `local_path` is compared by `samePath`, which resolves symlinks but does not
  absolutise. So the registry is generated by the target from `$(PWD)` and is
  the one part that cannot be committed.

## Summary of Changes

Shipped as `record-the-demo` (commit `f9aff83`).

Seven recordings in `demo/recordings/`, 2.5 MB, made against a fixture harbour
under `demo/` and shown in the README. `make demo` remakes them.

- **The fixture**: `harbour-app` reading its content from the `tideclock`
  store, plus `ferry-times` and `quay-signage` so the picker has rows. The
  store holds two specs, three archived changes and one change that stays
  active.
- **The active change carries all three operations** and a MODIFIED
  requirement whose scenarios are unchanged, edited and added, which is the
  only way the diff/old/new card is reproducible.
- **`make demo`** stages the fixture, generates the store registry from the
  staging path, builds spg from the checkout, stamps `RECORDED_AT`, and reports
  what is missing when vhs is absent.

## Three things found by recording and looking

- **The header publishes the absolute path.** Recording in the checkout put
  `/home/pim/gh.speclib/specgetty/...` in every frame. The fixture is now
  staged at `/tmp/specgetty-demo`, which also makes a clone at any path record
  the same content. Verified by cloning to another directory and reading the
  frame.
- **`make demo TAPES=...` silently recorded nothing.** The path was relative
  and the script cd s to the staging directory before running vhs. It failed
  into `>/dev/null`, and an earlier determinism check I ran was comparing a
  stale file with itself. Tape paths are now resolved before anything moves,
  and an unknown tape is an error.
- **VHS output is not reproducible.** Two recordings of one tape differ in
  frame count and in every pixel: the GIF encoder quantises a palette per file,
  so even identical screens hash differently. Tasks 5.3 and 5.4 were rewritten
  to verify what is true, which is that the content is fixed at the source.

## Corrected in the artifacts

`make demo` did nothing at first: the target name collides with the `demo/`
directory, so make reported it up to date. `.PHONY` fixes it.

The recordings had to become tracked rather than ignored, which the proposal
had backwards: the README shows them, so a GIF that exists only after
`make demo` is a broken image. That is 2.5 MB in the repository and the same
again in history on every re-record, now named in the design rather than
discovered later.
